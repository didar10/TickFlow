# TickFlow — как устроено приложение

Документ описывает архитектуру и логику приложения: из каких слоёв оно состоит, где хранятся данные, как работает каждый экран и какие правила действуют для задач, привычек и аналитики.

Стек: SwiftUI, SwiftData, Observation (`@Observable`), iOS 26. Язык интерфейса — русский.

---

## 1. Архитектура

Приложение разделено на три слоя. Правило одно: **во View нет логики, логика — во ViewModel, работа с базой — в Repository.**

```
View  ──(действия пользователя)──▶  ViewModel  ──(чтение/запись)──▶  Repository  ──▶  SwiftData / UserDefaults
  ▲                                     │
  └────(готовые данные для отрисовки)───┘
```

| Слой | Что делает | Чего не делает |
|---|---|---|
| **View** (`*View.swift`) | Рисует готовые данные из ViewModel, передаёт нажатия и жесты | Не считает даты, не фильтрует, не обращается к базе |
| **ViewModel** (`*ViewModel.swift`, `@MainActor @Observable`) | Готовит данные для экрана (строки, цвета, флаги), обрабатывает действия, показывает тосты и диалоги | Не знает про `ModelContext` |
| **Repository** (`Repositories/`) | Читает и пишет модели, перепланирует напоминания | Не форматирует тексты для экрана |
| **Shared** (`Shared/`) | Общая логика без UI: форматирование, конфликты, серии привычек, отмена | — |
| **Services** (`Services/`) | Уведомления, пример данных, экспорт | — |

### Данные для отрисовки

ViewModel отдаёт не модели SwiftData, а простые структуры с готовыми значениями: `TaskRowItem`, `CalendarItems.Card`, `HabitsViewModel.Row`, `InsightsViewModel.Report` и т.д. В них уже лежат строки («Сегодня, 11:00»), HEX-цвета и флаги («просрочено», «пересечение»). View их только раскладывает.

### Наблюдаемость

Репозитории — `@Observable`, их массивы (`tasks`, `lists`, `habits`, `settings`) перечитываются после каждого сохранения. Вычисляемые свойства ViewModel читают эти массивы, поэтому любой экран обновляется сам после любого изменения в базе.

### Сборка зависимостей

`App/AppDependencies.swift` — единственное место, где создаются репозитории и общие объекты. Там же фабрики всех ViewModel (`makeCalendarViewModel()`, `makeHabitEditorViewModel(request:)` …). View получает `AppDependencies` через `@Environment` и только вызывает фабрики.

Общие объекты, которые живут всё время работы приложения:

| Объект | Назначение |
|---|---|
| `SwiftDataRepository` | Задачи и категории (реализует `TaskRepository` и `TaskListRepository`) |
| `SwiftDataHabitRepository` | Привычки и их отметки |
| `UserDefaultsSettingsRepository` | Настройки |
| `ToastCenter` | Тосты с кнопкой «Отменить» |
| `TaskFilterStore` | Фильтр по категориям и статусу, общий для календаря и экрана задач |
| `AppNavigator` | Переходы между вкладками и экранами «извне» |

## 3. Модели данных

### SwiftData (`Models/`)

**`TaskList`** — категория («Работа», «Личное»…): имя, цвет (HEX), иконка, порядок. Удаление категории **каскадно удаляет её задачи**.

**`TaskItem`** — задача.

| Поле | Смысл |
|---|---|
| `title`, `notes` | Название и заметка |
| `dueDate` | Дата начала. Если `hasTime == false`, хранится начало дня |
| `hasTime`, `durationMinutes` | Есть ли время и длительность (для задач со временем) |
| `endDay` | Последний день многодневной задачи; `nil` — задача на один день |
| `priorityRaw` | `Priority`: нет / низкий / средний / высокий (`!`, `!!`, `!!!`) |
| `reminderRaw` | `ReminderOption`: нет / в момент начала / за 10 минут / за 1 час |
| `repeatRaw` | `RepeatRule`: никогда / каждый день / по будням / каждую неделю / каждый месяц |
| `isCompleted`, `completedAt` | Выполнение и его момент (нужен аналитике) |
| `createdAt`, `updatedAt` | Создание и изменение |
| `list`, `subtasks` | Категория и подзадачи (`Subtask`, удаляются вместе с задачей) |

Вычисляемые свойства: `endDate` (начало + длительность), `lastDay`, `isMultiDay`, `isOverdue` (последний день раньше сегодня), `occurs(on:)` (попадает ли задача на день), `reminderDate`.

**`Habit`** — привычка: имя, иконка, цвет, тип (`HabitKind`: да/нет, количество, время), цель на день `target`, единица, шаг нажатия `step`, частота (`HabitFrequency`: каждый день, по дням недели, N раз в неделю), дни недели (`1` — воскресенье … `7` — суббота), напоминание, дата начала. Отметки — `HabitLog` (удаляются вместе с привычкой).

**`HabitLog`** — отметка за день: значение `value` и флаг `isSkipped` (пропуск по желанию). Привычка выполнена за день, если `value >= target`.

### Настройки (`AppSettings`, хранятся в UserDefaults одним JSON)

Первый день недели, вид календаря по умолчанию и последний выбранный вид, 24-часовой формат, длительность новой задачи, тема, напоминания о задачах и привычках, напоминание по умолчанию, дни отдыха, «пропуски сохраняют серию», рабочие часы, `hasCompletedOnboarding`.

Декодер читает каждое поле через `decodeIfPresent`, поэтому новые поля не ломают старые сохранения.

### Черновики

Редакторы правят не модель, а черновик: `TaskDraft`, `HabitDraft`, `TaskListDraft`. В базу он попадает только по кнопке «Сохранить», поэтому «Отмена» ничего не меняет.

`TaskSnapshot` — полный снимок задачи (вместе с `id`), на нём построена отмена: `restore(snapshot)` возвращает задачу в прежнее состояние или создаёт заново с тем же `id`, если её удалили.

## 4. Репозитории

### `TaskRepository` (реализация — `SwiftDataRepository`)

| Метод | Что делает |
|---|---|
| `save(draft, to:)` | Создаёт задачу (`to: nil`) или обновляет существующую |
| `setCompleted(task, value)` | Отмечает выполнение. Для повторяющейся задачи **создаёт следующее вхождение** и возвращает его (см. §6.4) |
| `delete`, `duplicate`, `restore(snapshot)` | Удаление, копия «(копия)», восстановление для отмены |
| `schedule(at:)`, `setDuration`, `setDays`, `moveToToday` | Точечные изменения расписания |
| `rescheduleReminders(enabled:)` | Включает или выключает напоминания всех задач |

После каждого изменения репозиторий сохраняет контекст, перечитывает массив и перепланирует напоминание задачи.

### `HabitRepository` (реализация — `SwiftDataHabitRepository`)

`save(draft, to:)`, `delete`, `setValue(value, for:on:)` (значение `0` без пропуска удаляет отметку), `setSkipped(_, for:on:)`, `rescheduleReminders(enabled:)`.

### `SettingsRepository`

`settings` и `update { $0.поле = значение }`. Запись в UserDefaults происходит, только если значение изменилось.

## 5. Общая логика (`Shared/`)

| Файл | Назначение |
|---|---|
| `DisplayFormatter` | Все тексты дат и времени на языке интерфейса (`appLocale`). Учитывает 24-часовой формат и первый день недели из настроек. Создаётся во ViewModel из текущих настроек |
| `ConflictDetector` | Ищет незавершённую однодневную задачу со временем, которая пересекается с интервалом |
| `ScheduleCommit` | Сохранение расписания с учётом повтора (выбор «только это / это и следующие») и возвратом действия «Отменить»; текст про соседние задачи («Встык с «…»», «Перерыв всего N мин») |
| `TaskActions` | Отметить выполненной / удалить с тостом и отменой. Используется календарём, списком задач и поиском |
| `TaskFilterStore` | Фильтр по категориям и статусу (все / открытые / выполненные) |
| `TaskRowItem` | Готовая строка задачи: срок, категория, подзадачи «2/3», значки напоминания, повтора и пересечения |
| `ToastCenter` | Один тост за раз. Исчезает через 4,5 с; «Отменить» выполняет замыкание и показывает «Изменение отменено» |
| `HabitHistory`, `HabitText` | Состояния дней, серии, процент выполнения и тексты привычек (см. §8) |
| `AppNavigator` | Выбранная вкладка и запросы «открой создание задачи / привычки / настройки» с другого экрана |

Тексты интерфейса — в `Resources/L10n.swift` (константы) и `Resources/Localizable.xcstrings` (ru, en). Формы после числа (1 день, 2 дня, 5 дней) — plural-варианты каталога, `L10n.Plural.*`.

## 6. Задачи

### 6.1 Создание и редактирование (`Features/TaskEditor/`)

Редактор открывается через модификатор `.taskEditor($request)`, где `TaskEditorRequest` — `.new(day:startMinute:endDay:list:)` или `.edit(task)`.

- **Новая задача** открывается **панелью быстрого создания** (`QuickTaskPanel`): название, дата и время, категория, приоритет. Это не системный лист: панель лежит поверх всего приложения, прижата к клавиатуре и выезжает вместе с ней. Закрывается тапом по затемнению или смахиванием вниз.
- **Существующая** открывается **на весь экран**: всё то же плюс заметка, подзадачи, «Дублировать», «Удалить».
- «Открыть во весь экран» из шторки: шторка закрывается, затем открывается полноэкранный редактор с **тем же** ViewModel — введённое не теряется.
- Фокус на поле названия ставится только для новой задачи.

**Выбор даты** (`DateTimePickerViewModel`): вкладки «Дата» и «Период», быстрые варианты, календарь месяца, время с кнопками − и + (сдвиг начала сохраняет длительность), напоминание и повтор. Во вкладке «Период» нажатие на дату или время в «Начале» или «Конце» открывает карточку точного выбора: колёса «дата · часы · минуты» (точность до минуты), переключатель «Начало / Конец» и итоговая длительность. Сдвиг начала двигает конец с сохранением длительности; изменения попадают в задачу только по «Применить». Стрелки и −/+ работают как раньше. Если выбранное время пересекается с другой задачей, показывается предупреждение.

**Сохранение** (`TaskEditorViewModel.save()`):
1. Новая задача сохраняется сразу, тост «Добавлено · …» (с пометкой о пересечении), «Отменить» удаляет её.
2. Если ничего не изменилось, редактор просто закрывается.
3. Расписание изменилось у повторяющейся задачи → диалог «Только это вхождение / Это и следующие».
4. Расписание пересекается с другой задачей → диалог «Оставить обе / Отмена».
5. Сохранение через `ScheduleCommit`, тост с отменой.

### 6.2 Экран «Задачи» (`Features/Tasks/`)

- Поиск по названию, чипы категорий (общий фильтр с календарём), сортировка «Дата / Приоритет», обычный или компактный вид.
- Карточка «Сегодня»: «k из n выполнено» и полоса прогресса.
- **Группы:** Просрочено → Сегодня → Предстоящие → Без даты → Выполнено (сворачивается).
  - Просрочено — последний день задачи раньше сегодня.
  - Сегодня — начало не позже сегодня, а конец не раньше.
- Сортировка внутри группы по дате: раньше — выше; в один день задачи без времени выше задач со временем. По приоритету: высокий выше, внутри — по дате.
- «+» создаёт задачу на сегодня без времени.

### 6.3 Поиск и фильтр

- **Поиск** открывается из календаря на весь экран. Ищет по названию, заметке и имени категории; невыполненные идут выше выполненных. Есть подсказки-запросы.
- **Фильтр** — шторка с чипами категорий и статусом. Хранится в `TaskFilterStore`, поэтому действует и на календарь, и на список задач. Когда фильтр включён, на кнопке горит точка.

### 6.4 Повторяющиеся задачи

Упрощённая модель без «виртуальных» вхождений: в базе всегда есть ровно одна задача серии с правилом повтора.

- **Выполнение:** выполненное вхождение остаётся в истории с правилом «никогда», а репозиторий создаёт **следующее вхождение** с правилом повтора (`RepeatRule.nextDate(after:)`). Отмена выполнения удаляет созданное вхождение и восстанавливает исходное.
- **Изменение расписания** (в редакторе или перетаскиванием) спрашивает, к чему применить:
  - **«Это и следующие»** — меняется сама задача-серия;
  - **«Только это вхождение»** — задача становится разовой с новым временем, а серия продолжается отдельной задачей со следующей даты по старому расписанию.

### 6.5 Напоминания (`Services/NotificationScheduler`)

- У задачи напоминание ставится на `dueDate + смещение` (`ReminderOption.offset`), если у задачи есть время, момент в будущем, задача не выполнена и напоминания о задачах включены.
- У привычки — повторяющееся уведомление в заданное время: каждый день или по выбранным дням недели.
- Планирование проверяет разрешение **без системного запроса**. Сам запрос показывается только в онбординге («Включить напоминания»).
- При запуске, если онбординг пройден и уведомления разрешены, напоминания перепланируются.

## 7. Календарь (`Features/Calendar/`)

### 7.1 Виды и навигация

- **День, 3 дня, Неделя** — шкала времени. **Месяц** — сетка со списком дня.
- Шапка в одну строку: круглая кнопка вида (меню День / 3 дня / Неделя / Месяц), месяц и год, поиск, фильтр, «Сегодня».
- Горизонтальный свайп по заголовку, полосе дней или сетке месяца листает период: «День» — на неделю, «3 дня» — на 3 дня, «Неделя» — на неделю, «Месяц» — на месяц. Вертикальная прокрутка свайпом не считается.
- Нажатие на заголовок колонки в «3 дня» и «Неделе» открывает этот день в виде «День».
- Выбранный вид запоминается (`lastCalendarMode`). Смена «Вида по умолчанию» в настройках сразу переключает календарь.

### 7.2 Раскладка шкалы

- `TimelineGeometry`: высота часа — 64 pt в «Дне» и 52 pt в остальных видах, колонка подписей часов — 46 pt. Перевод пикселей в минуты идёт с шагом 15 минут.
- **Карточки** — однодневные задачи со временем. Пересекающиеся задачи (`TimeGridLayout.place`) делят колонку на дорожки и получают оранжевый значок «!».
- **Полоса «весь день»** — задачи без времени и многодневные. `TimeGridLayout.lanes` раскладывает их по рядам; если задача началась раньше видимого периода, к названию добавляется «‹ ».
- Линия «сейчас» обновляется раз в 30 секунд; подпись часа рядом с ней (±18 мин) и подпись «00:00» скрываются.
- При открытии шкала прокручивается к текущему времени (если на экране сегодня) или к началу рабочих часов.
- **Пустые состояния:** в базе нет ни одной задачи — карточка «Календарь пуст» (создать задачу / добавить привычку / загрузить пример); пустой день в виде «День» — подсказка «Ничего не запланировано».

### 7.3 Создание

- «+» создаёт задачу на выбранный день: на сегодня — на ближайший час, на другой день — на 9:00.
- Нажатие на пустое место шкалы создаёт задачу на это время (с округлением вниз до получаса).

### 7.4 Перетаскивание

Жест — UIKit-распознаватель удержания на 0,3 с (`TaskDragRecognizer`), поэтому обычная прокрутка шкалы ему не мешает. View передаёт во ViewModel только смещение пальца `dx`/`dy` (с поправкой на автопрокрутку) и ширину колонки; все правила — в `CalendarViewModel`.

| Что тянем | Режим | Результат |
|---|---|---|
| Карточку | `move` | Новое время (шаг 15 мин) и день |
| Нижний край | `resizeBottom` | Длительность (минимум 15 мин) |
| Верхний край (только в «Дне») | `resizeTop` | Начало при том же конце |
| Полосу «весь день» | `shiftDays` | Сдвиг на N дней |
| Левый или правый край полосы | `extendStart` / `extendEnd` | Начало или конец многодневной задачи |

Пока палец на экране:
- задача рисуется в новом месте, на старом — пунктирный контур;
- сверху чёрная плашка с новым временем и длительностью (и «Пересекается», если есть пересечение);
- каждый шаг сопровождается тактильным откликом;
- у краёв шкала прокручивается сама.

Когда палец отпущен:
1. Удержание без движения → меню «Выполнено / Открыть / Удалить».
2. Повторяющаяся задача → диалог выбора части серии.
3. Пересечение → диалог «Оставить обе».
4. Сохранение через `ScheduleCommit` и тост с отменой: «Перенесено на Завтра, 10:00 · Встык с «…»», «10:00 – 11:30 · 1 ч 30 мин», «Теперь 7 – 9 нояб.». Перенесённая карточка коротко подсвечивается.

### 7.5 Месяц

- В ячейке — до трёх точек и «+N». Цвет точки: серый — выполнено, красный — прошедший день, иначе цвет категории.
- Под сеткой — задачи выбранного дня («Весь день», «День 2 из 3», «10:00 – 11:00») и счётчик «k из n выполнено».

## 8. Привычки (`Features/Habits/`, `Shared/HabitHistory.swift`)

### 8.1 Состояние дня (`HabitDayState`)

Проверки идут по порядку, первая подходящая определяет состояние:

| Состояние | Когда |
|---|---|
| `done` | Значение за день ≥ цели |
| `skipped` | День пропущен по желанию |
| `notStarted` | День раньше даты начала привычки |
| `today` / `rest` | Сегодня: запланировано → `today`, иначе `rest` |
| `planned` / `rest` | Будущий день: запланирован или нет |
| `missed` / `rest` | Прошедший запланированный день без отметки → `missed`, незапланированный → `rest` |

У недельной цели («N раз в неделю») прошедшие дни без отметки считаются `rest`: пропустить конкретный день нельзя, важна только сумма за неделю.

### 8.2 Серии и статистика (`HabitHistory.stats`)

**Ежедневные привычки и привычки по дням недели:**
- **Текущая серия** — идём назад от сегодня. `done` прибавляет день; `rest` и невыполненное сегодня пропускаются; `skipped` пропускается, если включено «Пропуски сохраняют серию», иначе обрывает серию; `missed` обрывает.
- **Лучшая серия** — максимум за всю историю по тем же правилам.
- **Выполнение** — доля `done` среди `done + missed` за последние 30 дней.
- **Всего** — сколько дней цель была выполнена.

**Недельная цель:**
- Серия считается в **неделях** подряд, в которых цель выполнена. Текущая неделя засчитывается, только когда цель уже достигнута.
- Выполнение — выполненные дни за 4 недели относительно `N × 4`.

### 8.3 Экраны

- **Список.** Сводка дня: кольцо «выполнено / нужно сегодня» (учитываются запланированные на сегодня и уже выполненные), самая длинная серия, столбики по дням недели (доля выполненных среди учитываемых). Строка привычки показывает прогресс («1,25 / 2 л · Каждый день»), «День отдыха · …» или «Пропущено сегодня · серия сохранена», а также серию и кольцо.
  - **Кольцо:** нажатие прибавляет `step` (не больше цели); у выполненной привычки — сбрасывает. При выполнении — тост «Выполнено · серия N дней» с отменой.
  - Пустой список показывает подсказки: Чтение, Пить воду, Тренировка…
- **Детали.**
  - Четыре карточки статистики.
  - Месяц истории: листается назад, вперёд — не дальше следующего месяца; нажатие на день показывает его состояние.
  - Тренд за 8 недель и параметры привычки.
  - Кнопка «Пропустить сегодня / Отменить пропуск / Отметить как невыполненное» — с отменой.
- **Редактор.** Подсказки, название, иконка, цвет, тип, цель (шаг: 5 мин для времени, 0,25 л для литров, иначе 1), единица, частота, дни недели или «раз в неделю», напоминание. В режиме изменения есть удаление с подтверждением.
- Кнопка «Добавить первую привычку» на другом экране → `AppNavigator.openNewHabit()` → вкладка «Привычки» открывает редактор.

## 9. Аналитика (`Features/Insights/`)

Открывается из вкладки «Профиль» нажатием на карточку пользователя (push, кнопка «‹ Профиль»).

Всё считается по реальным данным в `InsightsViewModel.report` за один проход.

**Периоды:** неделя — последние 7 дней, месяц — 30 дней, год — 12 календарных месяцев. Каждый сравнивается с таким же предыдущим периодом.

| Показатель | Как считается |
|---|---|
| Выполнено | Задачи с `completedAt` в периоде |
| Создано | Задачи с `createdAt` в периоде |
| Выполнение | Доля выполненных среди задач со сроком в периоде. Сегодняшние невыполненные не учитываются: день ещё идёт |
| Просрочено | Невыполненные задачи, чей последний день в периоде и уже прошёл |

- **Изменение к прошлому периоду:** проценты (для «Выполнения» — процентные пункты). Зелёный — лучше, красный — хуже (для «Просрочено» наоборот). Если сравнивать не с чем — серое «Нет данных для сравнения».
- **График:** создано и выполнено по дням, неделям или месяцам; лучший столбик выделен. Хвост месяца короче 3 дней присоединяется к предыдущей неделе.
- **Выводы:** самый продуктивный день недели (больше всего выполнений), пиковые часы (двухчасовое окно с наибольшим числом выполненных задач со временем), среднее число выполненных задач в день.
- **Регулярность привычек:** у каждой привычки — доля `done` среди `done + missed` за период; общий показатель — среднее по привычкам, у которых в периоде были учитываемые дни.

## 10. Профиль и настройки (`Features/Profile/`)

Отдельного экрана настроек нет: все группы находятся во вкладке «Профиль» под карточкой пользователя. `AppNavigator.openSettings()` переключает на эту вкладку.

| Группа | Что есть |
|---|---|
| Оформление | Тема (как в системе / светлая / тёмная) — применяется в `RootView` |
| Календарь | Первый день недели, вид по умолчанию, 24-часовой формат, длительность новой задачи, рабочие часы |
| Уведомления | Напоминания о задачах и привычках (переключение сразу перепланирует), напоминание по умолчанию для новых задач со временем. Если уведомления запрещены в iOS — плашка со ссылкой в системные настройки |
| Категории | Список с числом задач, редактор, новая категория |
| Привычки | Дни отдыха, «Пропуски сохраняют серию» |
| Данные | Экспорт в JSON, загрузка примера, место хранения |
| О приложении | Версия, «Пройти знакомство заново» |

**Экспорт** (`ExportService`): категории, задачи с подзадачами и привычки с отметками сохраняются в JSON (даты в ISO 8601). Файл собирается в момент, когда пользователь выбрал, куда его отправить в меню «Поделиться» (`ExportFile: Transferable`).

**Редактор категории:** название, цвет (новой категории достаётся первый ещё не занятый цвет), иконка, удаление. В подтверждении удаления сказано, сколько задач удалится вместе с категорией.

## 11. Онбординг (`Features/Onboarding/`)

Показывается на весь экран, пока `hasCompletedOnboarding == false`.

1. **Приветствие.**
2. **Возможности:** календарь, задачи, привычки.
3. **Под себя:**
   - стиль планирования → вид календаря (блоки времени → «День», простой список → «Месяц» и вкладка «Задачи», всего понемногу → «Неделя»);
   - первый день недели;
   - рабочие часы;
   - цели → при завершении создаются соответствующие привычки (без повторов по имени).
4. **Напоминания:** «Включить напоминания» показывает системный запрос, «Не сейчас» его пропускает. Если шаг пропустили, прежние настройки уведомлений не меняются.
5. **Итог** — сводка выбранного и действия:
   - «Создать первую задачу» → календарь открывает создание задачи;
   - «Добавить первую привычку» → вкладка «Привычки» открывает редактор;
   - «Загрузить пример данных».

Редактор открывается с задержкой 0,6 с, после закрытия экрана знакомства: два экрана одновременно SwiftUI не покажет. «Пройти знакомство заново» переключает на вкладку «Задачи» и показывает знакомство.

## 12. Пример данных (`Services/SeedService`)

Загружается только по кнопке (онбординг, пустой календарь, настройки). Даты считаются относительно сегодняшнего дня.

- 5 категорий: Работа, Личное, Здоровье, Дела, Учёба.
- ~26 задач вокруг сегодняшнего дня: со временем, без времени, многодневные, повторяющиеся, с подзадачами, просроченные и выполненные.
- История выполненных задач за прошлые ~6 недель — чтобы аналитике было что сравнивать.
- 5 привычек с историей примерно за 120 дней. История детерминированная: графики выглядят одинаково при каждой загрузке.

## 13. Отмена действий

Почти каждое изменение показывает тост с кнопкой «Отменить». Замыкание отмены собирается **в момент действия**:

| Действие | Что делает «Отменить» |
|---|---|
| Создание задачи | Удаляет её |
| Выполнение задачи | Восстанавливает снимок; для повторяющейся — удаляет созданное следующее вхождение |
| Удаление задачи | Восстанавливает из снимка с тем же `id` |
| Перенос или изменение расписания | Восстанавливает снимок; при «Только это вхождение» удаляет отделившуюся серию |
| Отметка или пропуск привычки | Возвращает прежнее значение |
| Добавление привычки | Удаляет её |

Удаление привычки и категории не отменяется — для них есть подтверждение.

## 14. Как добавить новый экран

1. Создать `Features/<Имя>/<Имя>ViewModel.swift` — `@MainActor @Observable final class`. Зависимости (репозитории, `ToastCenter`, `AppNavigator`) передаются через `init` протоколами; наружу отдаются готовые структуры для отрисовки и методы-действия.
2. Создать `<Имя>View.swift` — `@State private var viewModel`, только разметка и вызовы методов ViewModel.
3. Добавить фабрику `make<Имя>ViewModel()` в `AppDependencies`.
4. Новые операции с данными добавлять в протокол репозитория и его реализацию, а не во ViewModel.
