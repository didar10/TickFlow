# TickFlow

Планировщик задач, расписания и привычек. SwiftUI + SwiftData, минимальная версия iOS 26, интерфейс на русском.

Подробно о том, как всё работает, — в [docs/APP_LOGIC.md](docs/APP_LOGIC.md).

## Запуск

```bash
open TickFlow.xcodeproj
```

Перед первым запуском поменяй `PRODUCT_BUNDLE_IDENTIFIER` (сейчас `com.ahito.TickFlow`)
и выбери свою команду подписи в Signing & Capabilities.

При первом запуске открывается знакомство с приложением. Пример данных загружается
кнопкой «Загрузить пример данных» на последнем шаге знакомства, на пустом календаре или в настройках.

## Что есть

- **Календарь.** Виды «День», «3 дня», «Неделя» (шкала времени) и «Месяц» (сетка и список дня).
  - Нажатие на свободное время создаёт задачу.
  - Удержание и перетаскивание переносит задачу на другое время или день, край карточки меняет длительность, края полосы «весь день» меняют дни многодневной задачи.
  - Пока тянешь — подсказка с новым временем. После переноса — тост с отменой.
  - Пересекающиеся задачи стоят рядом и помечены значком «!».
- **Задачи.** Группы: Просрочено, Сегодня, Предстоящие, Без даты, Выполнено. Поиск, чипы категорий, сортировка по дате или приоритету, компактный вид.
- **Редактор задачи.** Быстрое создание в шторке и полноэкранное редактирование. Дата, время или период, напоминание, повтор, приоритет, категория, подзадачи. Предупреждение о пересечении.
- **Повторяющиеся задачи.** Каждый день, по будням, каждую неделю, каждый месяц. Выполнение создаёт следующее вхождение. При изменении расписания можно выбрать «Только это вхождение» или «Это и следующие».
- **Привычки.** Три типа: да / нет, количество, время. Частота: каждый день, по дням недели или N раз в неделю.
  - Серии, лучшая серия, процент выполнения, история по месяцам, тренд за 8 недель.
  - Пропуск дня не прерывает серию (если это включено в настройках).
- **Аналитика.** Выполнено, создано, процент выполнения, просрочено — за неделю, месяц или год в сравнении с прошлым периодом. График активности, продуктивный день недели, пиковые часы, регулярность привычек.
- **Настройки.** Тема, первый день недели, вид по умолчанию, 24-часовой формат, длительность задачи, рабочие часы, напоминания, категории, правила привычек, экспорт в JSON.
- **Знакомство.** Пять шагов: настройки под себя, цели-привычки и запрос уведомлений.
- **Отмена.** Почти каждое изменение показывает тост «Отменить».
- **Напоминания.** Локальные уведомления для задач со временем и для привычек.

## Структура

```
TickFlow/
├── TickFlowApp.swift        ModelContainer и точка входа
├── RootView.swift           Вкладки: Календарь / Задачи / Привычки / Аналитика; тосты, знакомство, настройки
├── App/                     AppDependencies (сборка зависимостей, фабрики view model), RootViewModel
├── Models/                  TaskItem, TaskList, Subtask, Habit, HabitLog, AppSettings, перечисления
├── Repositories/            Протоколы и реализации: задачи и категории, привычки (SwiftData), настройки (UserDefaults)
├── Services/                Уведомления, пример данных, экспорт
├── Shared/                  Общая логика без UI: форматирование дат, пересечения, серии привычек, отмена, навигация
├── DesignSystem/            Цвета и шрифты из макета, общие компоненты
└── Features/                Calendar, Tasks, TaskEditor, Search, Filter, Habits, Insights,
                             Settings, Lists, Onboarding — у каждого экрана View и ViewModel
```

## Архитектура

`View → ViewModel → Repository → SwiftData / UserDefaults`

- **View** только рисует готовые данные и передаёт действия. Логики в ней нет.
- **ViewModel** (`@MainActor @Observable`) готовит данные для экрана: строки, цвета, флаги. Обрабатывает действия, показывает тосты и диалоги.
- **Repository** — единственное место, где используется `ModelContext`. Он же перепланирует напоминания. ViewModel зависят от протоколов.
- Экраны обновляются сами: репозиторий перечитывает данные после каждого изменения, наблюдение (Observation) перерисовывает экраны.
- Редакторы правят черновики (`TaskDraft`, `HabitDraft`). В базу черновик попадает только при сохранении.

Проект использует синхронизированные группы Xcode (`PBXFileSystemSynchronizedRootGroup`):
новые файлы внутри папки `TickFlow/` попадают в таргет автоматически, редактировать
`project.pbxproj` не нужно.

## Осознанные упрощения

1. **Фильтрация в памяти.** Репозиторий держит все задачи в памяти, отбор идёт в view model.
   На сотнях задач это незаметно, на десятках тысяч — нет. Переход на `#Predicate` стоит делать вместе с пагинацией.
2. **Упрощённые повторы.** В базе хранится одна задача серии. Следующее вхождение создаётся при выполнении, а не заранее. Поэтому будущие вхождения не видны в календаре, а правила вида «каждый второй вторник» не поддерживаются.
3. **Нет синхронизации и аккаунтов.** Данные хранятся только на устройстве. Модели написаны с учётом CloudKit: у всех свойств есть значения по умолчанию, уникальных ограничений нет.
4. **Задача через полночь** на шкале обрезается концом дня.
5. **Задачу из полосы «весь день» нельзя перетащить на шкалу** — время задаётся в редакторе.
6. **Удаление категории удаляет её задачи.** Перед удалением показывается подтверждение с числом задач.
7. **Ручная сортировка.** `sortOrder` есть в модели, но перетаскивание в списке не подключено.
8. **Нет тестов.** Тестового таргета в проекте пока нет.
